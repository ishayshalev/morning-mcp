# מה נבדק

הבדיקות מפעילות את שרת ה־MCP דרך stdio עם מפתחות פיקטיביים ו־API מדומה. כל בקשת רשת של שרת הבדיקה נחסמת או נענית מקומית. אין שימוש במפתחות שלכם ואין פעולה בחשבון מורנינג אמיתי.

- כל 28 הקריאות ו־27 הפעולות העסקיות בקטלוג.
- אישור, סירוב וביטול דרך בקשת אישור MCP, כולל האישור המוקלד לחיוב, מחיקה ואיחוד.
- חסימת אישורים מזויפים, פגי תוקף, אישורים לטיוטה אחרת ובקשות חוזרות.
- חסימת שינוי תוכן, כותרת, תאריך, PDF, קובץ הוצאה או חיבור אחרי הכנת הטיוטה.
- בקשות מקבילות משני תהליכים מבצעות לכל היותר פעולה אחת. אחרי תוצאה לא ודאית, הבקשה נשארת חסומה גם בהפעלה מחדש.
- טופס מקומי: שמירה פרטית, אישור החלפה, חסימת אתר אחר, תפוגה ושגיאות שמירה.
- טופס בדפדפן: הצלחה, כשל ותגובה שנתקעה. יש חיווי מיידי, הודעת אישור או שגיאה, ואפשרות לנסות שוב.
- שמירה ועדכון מיידיים של טיוטה במורנינג, קריאה, חיפוש ותצוגת PDF.
- הפקה מהטיוטה השמורה: קישור draftId, בדיקת תוכן ונמענים, חסימת עריכה אחרי review, חסימת PDF שהשתנה וסירוב להשמיט שדות כספיים לא מוכרים.
- ניסיון שמירה חוזר עם אותו מפתח בקשה, שני תהליכים במקביל ותוצאה לא ודאית אינם יוצרים טיוטה נוספת.
- MCP זמין לפני הזנת מפתחות, וטוען מפתחות שנשמרו בלי הפעלה מחדש.

מסלולי האישור נבדקו בפרוטוקולים 2025-06-18, 2025-11-25 ו־2026-07-28. לקוח ללא חלון אישור יכול לקרוא ולשמור טיוטות מסמכים, אך אינו יכול להפיק, לשלוח או לבצע שינויים אחרים. אלה בדיקות של הפרוטוקול; הן אינן מוכיחות שהחלון מוצג בכל גרסה של Codex או Claude.

77 הבדיקות עברו ב־macOS עם Node 22.23.3 ו־Node 25.5.0. בדיקות GitHub רצות גם ב־Linux וב־Node 24. בדיקת התלויות של npm לא מצאה חולשות ידועות ב־7 באוקטובר 2026.

## הרצה

מתוך תיקיית המאגר, אחרי התקנת התלויות:

<pre dir="ltr"><code>npm ci --ignore-scripts
npm run check
npm test</code></pre>

בדיקות הטופס פותחות שרת זמני ב־127.0.0.1. צריך לאפשר גישה ל־loopback אם סביבת הפיתוח חוסמת אותה. הנתונים נכתבים לתיקייה זמנית ונמחקים בסיום.

## בדיקה חיה ב־7 באוקטובר 2026

בוצעה דרך MCP ו־API עם מפתח עסקי רגיל, ללא Cookies או דפדפן: אימות, שמירת טיוטת הצעת מחיר פיקטיבית של ₪1, קריאה חוזרת, עדכון, ניסיון חוזר עם אותו מפתח בקשה ללא יצירת עותק, חיפוש, יצירת PDF מתוך הטיוטה השמורה והכנת בקשת הפקה מקומית. הטיוטה נשמרה במורנינג. החיפוש הציג אותה אחרי השהיה קצרה.

לא אושרה בקשת הפקה, לא הונפק מסמך, לא נשלח מייל, לא בוצע חיוב ולא הועלתה הוצאה. מסלולי הפקה, מחיקה, שכפול ושאר השינויים נבדקו אוטומטית מול API מדומה. הצגת חלון האישור בכל גרסת Codex או Claude והפקה חיה דורשות בדיקה עם המשתמש כשבאמת רוצים להפיק מסמך.

המפרט הציבורי של [Morning](https://developers.morning.co/docs/openapi.bundled.json) נבדק מחדש ב־7 באוקטובר 2026. זו גרסה 2.0.0, עם 54 פעולות. נוספו 7 פעולות לטיוטות מסמכים שנצפו בקוד הציבורי של האפליקציה, בנפרד מהמפרט. [כיסוי מלא והחריגים](../API-COVERAGE.md).
