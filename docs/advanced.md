# עוד קצת פרטים

המפתחות נשמרים בקובץ פרטי <code dir="ltr">~/.morning-mcp/config.json</code>; בקשות אישור וקבצים נשמרים בנפרד לכל חשבון וסביבה תחת <code dir="ltr">~/.morning-mcp/data/</code>. הם **לא נמחקים אוטומטית**. הרשאות הקבצים במק וב־Linux מוגבלות לבעלים; אין הצפנת Keychain. אין לתת לסוכן גישה ישירה למפתחות. מנגנון האישור מסתמך על האפליקציה שמציגה אותו; אין להגדיר בה אישורים אוטומטיים.

החסימה חלה על פעולות דרך שרת ה־MCP. סוכן עם גישה לקבצים ולטרמינל באותו משתמש מערכת יכול לקרוא את קובץ המפתחות או לפנות ישירות ל־API. בידוד מלא דורש הגבלת הרשאות הסוכן ברמת מערכת ההפעלה.

הקטלוג כולל 54 פעולות מתועדות ועוד 7 פעולות לטיוטות מסמכים שנצפו באפליקציה של מורנינג. טיוטות מסמכים נשמרות במורנינג מיד; הפקה, שליחה וכל שינוי עסקי אחר עוברים דרך אישור. אימות והעלאת קובץ מנוהלים פנימית. פעולות שותפים וקבלת Webhooks אינן ממומשות. זהו כיסוי בקוד ובסכמות, לא אימות חי של כל פעולה. [רשימת הפעולות והחריגים](../API-COVERAGE.md).

## התקנה ידנית

<pre dir="ltr"><code>git clone https://github.com/ishayshalev/morning-mcp.git
cd morning-mcp
npm ci --ignore-scripts
node bin/morning-mcp.mjs setup</code></pre>

הפקודה האחרונה פותחת טופס מקומי בדפדפן. מדביקים בו מזהה וסוד ושומרים. אין הרשמה נוספת. אפשר להשתמש ב־<code dir="ltr">setup --no-open</code> לקבלת קישור מקומי, או ב־<code dir="ltr">setup --terminal</code> להזנה במסוף פרטי עם סוד מוסתר. אל תזינו מפתחות במסוף שהסוכן קורא.

מוסיפים ללקוח MCP את הנתיב המלא ל־Node ואת הנתיב המלא ל־<code dir="ltr">bin/morning-mcp.mjs</code>. [דוגמת Codex](../examples/codex.toml) · [דוגמת Claude Desktop](../examples/claude-desktop.json) · [פקודות והוראות לכל לקוח](INSTALL-AGENT.md).

## הגדרות נוספות

אפשר להשתמש במשתני סביבה במקום קובץ: מגדירים **גם** <code dir="ltr">MORNING_CLIENT_ID</code> **וגם** <code dir="ltr">MORNING_CLIENT_SECRET</code>. ברירת המחדל של <code dir="ltr">MORNING_ENV</code> היא <code dir="ltr">production</code>.

| הגדרה אופציונלית | שימוש |
| --- | --- |
| <code dir="ltr">MORNING_CONFIG_FILE</code> | נתיב אחר לקובץ המפתחות |
| <code dir="ltr">MORNING_DATA_DIR</code> | תיקייה אחרת לטיוטות ולקבצים |
| <code dir="ltr">MORNING_WRITES_ENABLED=false</code> | חסימת כל כתיבה, כולל שמירת טיוטה במורנינג; קריאה והכנת בקשות מקומיות עדיין זמינות |

חלון האישור משתמש בהמשך בקשה חתום, התקף לעשר דקות. הטיוטה תקפה ל־24 שעות; הכותרת, התוכן והתצוגה המקדימה נקשרים לאישור. הפעלה מחדש דורשת אישור חדש. השרת טוען מפתחות שנשמרו או הוחלפו בלי הפעלה מחדש. התנהגות הרשאות הקבצים ב־Windows לא נבדקה.

[הוראות ההתקנה לסוכן](INSTALL-AGENT.md) כוללות את פקודות ההתקנה והגדרת הלקוחות. החיבור פועל עם Node והנתיב המלא לקובץ השרת.

בדיקות אוטומטיות מכסות את כל 28 הקריאות ו־27 הפעולות העסקיות מול API מדומה, דרך MCP אמיתי ב־stdio. נבדקו אישור, סירוב, ביטול, זיוף אישור, שינוי טיוטה, בקשות מקבילות, תוצאה לא ודאית, החלפת מפתחות והעלאות קבצים. טופס ההגדרה נבדק גם בדפדפן, כולל הצלחה, שגיאה ותגובה שנתקעה. [פירוט והרצת הבדיקות](TESTING.md).

אימות API ושמירה, עדכון, קריאה וחיפוש של טיוטת בדיקה במורנינג נבדקו בחשבון אמיתי ב־7 באוקטובר 2026. לא הונפקה חשבונית, לא נשלח מייל, לא בוצע חיוב ולא הועלתה הוצאה. חלון האישור בכל גרסת לקוח והפקה חיה עדיין דורשים בדיקה עם המשתמש.
